# Telegram AI Assistant with Long-Term Memory

**Персональный Telegram-бот с векторной памятью на базе Pinecone и OpenAI**

Бот ведёт осмысленные диалоги, помня контекст общения благодаря векторной базе данных **Pinecone**. Каждое сообщение анализируется на сходство с уже сохранёнными — новая информация добавляется, похожая обновляется.

## 🚀 Возможности

- **Связный диалог** — краткосрочная история последних реплик (RAM) подмешивается в промпт, бот продолжает разговор и понимает «а теперь про него»
- **Долговременная память** — векторный поиск релевантных фрагментов по запросу
- **Память об ответах бота** — каждое сообщение пользователя и компактное резюме ответа сохраняются в память; резюме подмешиваются в контекст только на явный вопрос «что ты мне говорил/отвечал»
- **Консолидация памяти «как сон»** — раз в сутки LLM сжимает записи старше недели в дайджесты (`memory_digest`), оригиналы удаляются: база не растёт бесконечно
- **/forget** — ручная очистка диалоговой памяти (с подтверждением, документы остаются)
- **Документы → Pinecone** — скиньте `.txt`, `.md`, `.pdf` или `.docx`; бот извлечёт текст, нарежет чанки и проиндексирует в векторную базу, после чего отвечает по содержимому
- **Изоляция по пользователям** — память и документы разделены по `user_id` Telegram
- **Умное сохранение** — новые сведения добавляются, похожие обновляются
- **LLM-арбитраж конфликтов** — в «серой зоне» сходства (0.65–0.85) дешёвый вызов модели решает: уточнение того же факта, противоречие (перезаписывается) или независимый факт
- **Устойчивость к нестабильному интернету** — ретраи с экспоненциальной паузой у Pinecone и Telegram, свои ретраи и таймауты у OpenAI SDK
- **Настраиваемый порог** — контроль сходства через `MEMORY_COSINE_SIMILARITY_HIGH_THRESHOLD`
- **Прозрачность** — логирование: сохранён / обновлён / пропущен фрагмент

## ⚙️ Установка

### Требования

- Python 3.10+
- Аккаунты: **OpenAI**, **Pinecone**, токен бота от [@BotFather](https://t.me/BotFather)

### Требования к Pinecone

- **Метрика**: `cosine` (иначе интерпретация score будет некорректной)
- **Размерность**: должна совпадать с моделью эмбеддингов (`text-embedding-3-small` → **1536**)

### Шаги

```bash
# 1. Клонировать репозиторий
git clone https://github.com/CherkasovAV/telegram-ai-assistant.git
cd telegram-ai-assistant

# 2. Создать виртуальное окружение
python -m venv venv

# 3. Активировать
# Windows:
venv\Scripts\activate

source venv/bin/activate

# 4. Установить зависимости
pip install -r requirements.txt

# 5. Настроить переменные окружения
cp .env.example .env
```

## 🔐 Настройка окружения

Отредактируйте `.env`:

```env
# Telegram Bot Token
TELEGRAM_BOT_TOKEN=your-bot-token-here

# OpenAI API
OPENAI_API_KEY=sk-your-api-key-here
# OPENAI_BASE_URL=https://api.proxyapi.ru/openai/v1

# Pinecone
PINECONE_API_KEY=pcsk_your-api-key-here
PINECONE_INDEX_NAME=your-index-name

# Опционально
OPENAI_CHAT_MODEL=gpt-4o-mini
PINECONE_ENVIRONMENT=us-east-1
```

| Переменная | Обязательна | Описание |
|------------|-------------|----------|
| `TELEGRAM_BOT_TOKEN` | Да | Токен бота от @BotFather |
| `OPENAI_API_KEY` | Да | Ключ OpenAI (чат + эмбеддинги) |
| `PINECONE_API_KEY` | Да | Ключ Pinecone |
| `PINECONE_INDEX_NAME` | Да | Имя индекса |
| `OPENAI_BASE_URL` | Нет | Свой endpoint (прокси, совместимый API) |
| `OPENAI_CHAT_MODEL` | Нет | Модель чата (по умолчанию `gpt-4o-mini`) |
| `PINECONE_ENVIRONMENT` | Нет | Регион (по умолчанию `us-east-1`) |
| `DIALOG_HISTORY_TURNS` | Нет | Глубина краткосрочной истории: пар реплик (по умолчанию `6`) |
| `NETWORK_RETRY_ATTEMPTS` | Нет | Сколько раз повторять сетевые вызовы (по умолчанию `4`) |
| `NETWORK_RETRY_BASE_DELAY` | Нет | Начальная пауза между ретраями, сек (по умолчанию `2`) |
| `NETWORK_RETRY_MAX_DELAY` | Нет | Максимальная пауза между ретраями, сек (по умолчанию `30`) |
| `OPENAI_MAX_RETRIES` | Нет | Ретраи OpenAI SDK (по умолчанию `5`) |
| `OPENAI_TIMEOUT` | Нет | Таймаут OpenAI SDK, сек (по умолчанию `90`) |
| `DOC_CHUNK_SIZE` | Нет | Размер чанка документа в символах (по умолчанию `1200`) |
| `DOC_CHUNK_OVERLAP` | Нет | Перекрытие соседних чанков (по умолчанию `200`) |
| `DOC_MAX_CHUNKS` | Нет | Предел чанков на один файл (по умолчанию `150`) |
| `ASSISTANT_SUMMARY_CHARS` | Нет | Длина резюме ответа бота в памяти (по умолчанию `300`) |

## 🎯 Использование

### Запуск

```bash
python telegram_bot.py
```

### Документы

Отправьте бот файл `.txt`, `.md`, `.pdf` или `.docx` (до 20 МБ — лимит Telegram Bot API). Бот:

1. скачивает файл;
2. извлекает текст (для `.txt`/`.md` есть фолбэк кодировок utf-8 → cp1251);
3. нарезает на чанки заданного размера с перекрытием;
4. векторизует и записывает в Pinecone с метаданными `user_id`, `type=file_chunk`, `file_name`, `chunk_index`.

Старый бинарный формат `.doc` не поддерживается — пересохраните документ в `.docx`.

История диалога хранится в RAM и сбрасывается при перезапуске бота; долговременная память в Pinecone сохраняется.

В логах (уровень INFO) видно, когда фрагмент:
- **Сохранён** — новая информация
- **Обновлён** — найдено высокое сходство с существующим
- **Пропущен** — если изменён режим на `skip`

## 🧠 Как работает память

### Архитектура `PineconeManager`

```python
class PineconeManager:
    - create_embedding()        # Создание эмбеддинга текста
    - query_by_text()           # Поиск по текстовому запросу
    - query_by_vector()         # Поиск по вектору
    - upsert_documents()        # Пакетная запись
    - remember_document()       # Умное сохранение с проверкой сходства
    - assess_memory_similarity() # Оценка сходства без записи
    - delete() / delete_all()   # Удаление
    - update_metadata()         # Обновление метаданных
```

### Логика ответа

1. Пользователь отправляет сообщение
2. Векторный поиск по Pinecone: память пользователя + проиндексированные чанки его документов
3. В модель уходят: system-промпт с выдержками + краткосрочная история диалога + новое сообщение
4. Ответ пользователя и ответ бота сохраняются в долговременную память (с проверкой сходства, порог как в `PineconeManager`)

### Логика сохранения

1. Сходство ≥ `0.85` → дубль/вариация: перезапись существующего слота (или пропуск)
2. Сходство в серой зоне `0.65–0.85` → LLM-арбитр: `same`/`contradiction` — обработка как дубль (перезапись), `unrelated` — новая запись
3. Сходство `< 0.65` → добавляется как новая запись
4. Документы записываются как чанки `type=file_chunk`, сообщения — `type=user_message`, резюме ответов бота — `type=assistant_summary`

## 🔍 Устранение неполадок

### Ошибки подключения к Pinecone

- Проверьте `PINECONE_API_KEY` и `PINECONE_INDEX_NAME`
- Убедитесь, что индекс существует и доступен
- Проверьте метрику индекса (`cosine`)

### Ошибки подключения к Telegram

- Проверьте `TELEGRAM_BOT_TOKEN`
- При проблемах с сетью задайте `TG_PROXY_URL`
- Убедитесь, что запущен только один экземпляр бота

### Бот не отвечает

- Проверьте логи на наличие таймаутов
- Убедитесь, что `getMe` проходит успешно
- Проверьте, что индекс Pinecone не пуст
